# Install types and settings

One page for the four install shapes. Facts below come from `tools/build_msix.py`, `docs/IT_DEPLOYMENT.md`, `app/policy.py`, `installer/policy/QuantiSheet.admx` (+ `en-US/QuantiSheet.adml`), and the installer scripts those documents describe (`installer/quantisheet.iss`, `installer/quantisheet_server.iss`, `tools/make_msi.py`, `app/updatecheck.py`, `app/storeupdate.py`, `app/settings.py`, `app/packaged.py`, `app/shellverbs.py`). Anything those files do not settle is marked **TO CONFIRM**.

| | Per-user installer | Per-machine / IT installer | MSIX / Store | Portable |
|---|---|---|---|---|
| Program | `installer/quantisheet.iss`. `PrivilegesRequired=lowest`, so a current-user install needs no administrator. Default folder `{autopf}\QuantiSheet`, which the IT guide states as `%LOCALAPPDATA%\Programs\QuantiSheet`. The first page can raise the same setup to all users (`PrivilegesRequiredOverridesAllowed=dialog`); an upgrade stays in the folder already recorded for AppId `{375F90B3-3B41-4FE9-B790-B29C6D30C75E}`. | `installer/quantisheet_server.iss` (`PrivilegesRequired=admin`, `{commonpf64}\QuantiSheet`, IT guide: `C:\Program Files\QuantiSheet`, AppId `{6A0E2C4B-9F31-4D2B-8C55-3B1D2E7F9A40}`) and `tools/make_msi.py` (same program, per machine, same folder, for Intune / SCCM / GPO). The server setup creates `C:\ProgramData\QuantiSheet` and locks it to SYSTEM and Administrators. | `tools/build_msix.py` packs the public one-folder build, writes `AppxManifest.xml`, and runs MakeAppx. Windows chooses the package folder. **TO CONFIRM** the exact path (it is not hardcoded). Package name and publisher come from `installer/msix_identity.json` (placeholders until Partner Center values are filled). `mark_store` sets `edition` to `store`. | No portable installer, script, or output name exists in the sources above. `tools/ship_check.py` names "portable / team zips" only as a place licensed price data must not be packed. `tools/zip_release.py` zips the setup exe. The PyInstaller one-folder tree (`quantisheet.spec`, built under `%LOCALAPPDATA%\QuantiSheetBuild` by `tools/build_installer.py`) can be copied. **TO CONFIRM** whether that copy is a supported install. |
| Settings and data | `%USERPROFILE%\.quantisheet` (`app/settings.py`: `settings.json`, logs unless `LogDirectory` is set). Price database in that per-user area unless `PriceDatabasePath` is set. IT guide also places the code library and print-helper log in `%LOCALAPPDATA%\QuantiSheet`, and printed PDFs in `Documents\QuantiSheet\Printed`. This setup does not create `C:\ProgramData\QuantiSheet`. `app/policy.py` still reads `%ProgramData%\QuantiSheet\policy.json` when an administrator owns that file. | Same per-user settings folder (the path is the home directory, not the install directory). Machine data, policy file, relay files, and the printer spool live in `C:\ProgramData\QuantiSheet`, which this setup creates. Uninstall removes the program and the policy values the setup wrote; the IT guide says each user's `.quantisheet` folder is left in place. | `app/packaged.py` tells the person that a side-by-side setup's settings, jobs, and price database stay in use. The settings path in code is still `%USERPROFILE%\.quantisheet`. **TO CONFIRM** whether MSIX file virtualization redirects that folder. The manifest does not declare a private data path. | A copied folder still resolves settings through `app/settings.py` (`%USERPROFILE%\.quantisheet`). Nothing in the copy creates ProgramData or registers policy. |
| Updates | Offline-first: the IT guide states that opening, markup, measuring, estimating, and printing do not use the network. `app/updatecheck.py` has one channel string, `team`, and one manifest URL. There is no ring list. A frozen tester build outside an MSIX package may GET that manifest at most once a day, and again from Help > Check for Updates Now. The person must click Update now. The download stays on `DOWNLOAD_HOSTS`, the SHA-256 is checked, and a mismatch deletes the file. Quiet switches do not ask Windows to elevate. The updater stores `QuantiSheet-Team-Setup-<version>.exe`. The build names this setup `QuantiSheet-Beta-Setup-<version>.exe`. These line up: the downloader always saves what it fetches as `QuantiSheet-Team-Setup-<version>.exe` (`updatecheck.installer_path`), whatever the published name, and `previous_installer` looks for that same name. A public edition does not check (`team_build()` is false). `OfflineMode` or `DisableUpdateCheck` turns the check off, as does the setting `update_check_enabled`. 1.1.1: the manifest names the installer's code-signing thumbprint and the download must be signed by it (`updatecheck.signed_by`); the installer of the version now running is kept in the download folder (`updatecheck.tidy`, `previous_installer`), so it can be run again by hand after a bad update. There is no Roll Back command in the app. | Same check, because eligibility follows the build stamp, not the install folder. The server script uses Restart Manager so running copies are asked to close. The IT guide says to run those updates out of hours. The in-app launch path does not elevate, and this install needs an administrator. **TO CONFIRM** a quiet update into `C:\Program Files\QuantiSheet`. | The Store copy never downloads its own installer (`updatecheck._in_package` / `team_build`). `app/storeupdate.py` asks the local Store (`StoreContext`) whether an update is waiting and can open the Store page. QuantiSheet does not download the package. The same `DisableUpdateCheck`, `OfflineMode`, and `update_check_enabled` switches apply. `tools/build_msix.py` does not sign or submit the package. | If the copied folder is a frozen tester build and not an MSIX package, `team_build()` does not look at the path, so the team check would run. **TO CONFIRM**, because no portable package is produced. |
| Group policy | The reader is the same for every copy (`app/policy.py`): HKLM then HKCU `Software\Policies\QuantiSheet`, then `%ProgramData%\QuantiSheet\policy.json`. Policy.json is ignored unless SYSTEM, Administrators, or TrustedInstaller owns it. `LicenseKey`, `AcceptAgreement`, and `SkipEmailSignIn` are registry-only. This setup writes no policy values and does not install the ADMX. Keys already on the PC still apply. | The server `gpo` task (on by default) copies `QuantiSheet.admx` / `.adml` into PolicyDefinitions. Both files also sit in the program's `policy\` folder. The MSI can do the same (`GPO=1`, documented as the default). Install-time switches write a subset under HKLM: `LicenseKey`, `PriceDatabasePath`, `RelayURL`, `AIHost`, `LogDirectory`, `AcceptAgreement`, `SkipEmailSignIn`, `OfflineMode`, `DisableAI` (`quantisheet_server.iss`, `tools/make_msi.py` `POLICY_VALUES`). | The manifest ships no ADMX. `app/policy.py` has no MSIX branch. **TO CONFIRM** that a packaged process sees HKLM `Software\Policies\QuantiSheet` rather than a virtualized view. | No template is installed with a copied folder. The same reader still applies if the keys are already on the PC. |
| Right-click verbs | Task `shellverbs` (on by default) writes `HKA` keys, so a per-user install uses HKCU and an all-users run of this same setup uses HKLM. Verbs (`app/shellverbs.py`): PDF **Open in QuantiSheet** and **Reduce size** (`--qs-reduce`); **Convert to PDF** (`--qs-convert`) on `.doc .docx .rtf .odt .xls .xlsx .xlsm .csv .ods .ppt .pptx .odp .txt .md .html .htm .png .jpg .jpeg .tif .tiff .bmp .gif`; folders **Combine PDFs** (`--qs-combine-folder`) on `Directory` and `Directory\Background`. Task `openwith` (also on by default) adds ProgID `QuantiSheet.pdf` and does not take the default PDF app. `.qstools` double-click is registered with the setup, outside that task. | Open-with only. Server setup and MSI register ProgID `QuantiSheet.Server.pdf` (`shell\open` runs the exe with `%1`). No Reduce, Convert, or Combine keys are in `quantisheet_server.iss` or `tools/make_msi.py`. | The manifest declares file-type associations for `.pdf` and `.qstools`. It declares no Reduce, Convert, or Combine verb. | Copying the folder writes no registry verbs. |

Policy names in `app/policy.py` `SETTINGS` and in the ADMX (same set, `class="Both"`): `LicenseKey`, `AcceptAgreement`, `SkipEmailSignIn`, `PriceDatabasePath`, `RelayURL`, `RelayToken`, `AIHost`, `LogDirectory`, `OfflineMode`, `DisableAerial`, `DisableWeather`, `DisableRateLookup`, `DisableDocuSign`, `DisableDropbox`, `DropboxAppKey`, `DisableAI`, `DisableUpdateCheck`, `DisablePackageStatus`. 1.1.1 adds `DisablePackageStatus` to `SETTINGS` and the ADMX (on 1.0.7 it was missing, so `policy.get` raised `KeyError`, the caller swallowed it and the switch did nothing).

Signing: `docs/IT_DEPLOYMENT.md` states the installers are not code-signed yet. `tools/codesign.py` signs the built exe and the setups only after a certificate config exists outside the repo; until then the build leaves them unsigned. `tools/build_msix.py` does not sign the package; the Store signs it after certification. A placeholder identity is not for submission.

**TO CONFIRM (open):** MSIX install path and whether the package virtualizes `%USERPROFILE%\.quantisheet` or HKLM policy; whether a loose one-folder copy is a supported portable install; a quiet update into Program Files.

## Signing timestamps (Venice #3, Nov 4)

Setting `timestamp_url` (File > Signing Timestamp Server…). Default: empty,
so timestamping is OFF and signing never goes online; a signature's time is
then the PC's clock. When set, sign_pdf asks that RFC 3161 server for a
trusted time (app/sign/timestamp.py). A commonly used free server is shown
as a suggestion (SUGGESTED_TIMESTAMP_URL) but is never used unless typed in.
